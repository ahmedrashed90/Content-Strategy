# MZJ | Content Strategy Foundation v1.1.0

نظام مستقل لصاحب حساب واحد، لإدارة المرجع التاريخي لأداء Facebook وInstagram وTikTok وSnapchat قبل بدء استراتيجية المحتوى. جميع الوظائف المستمرة (الإنتاج والنشر وربط المبيعات) لا تزال مؤجلة حتى تحليل إجابات الإدارة الـ45.

**ما تغير في 1.1.0**

- إضافة أرقام Snapchat Insights الحقيقية للفترة **10 أكتوبر – 6 نوفمبر 2026**، مع تفصيل Profile Stories وPublic Stories وSpotlight؛ لا تُجمع مشاهداتها في رقم واحد.
- إعداد مرجع موحّد جديد `baselines/baseline-2026-v2` يتضمن الأربع منصات. **نسخة v1 القديمة تبقى كما هي، ولا يمسحها النظام ولا يعدلها.**
- إضافة بطاقات Snapchat ولوحة تفصيلية بأرقام المشاهدات والمشاهدين ومدة المشاهدة ومصادر زيارات الملف والعمر والمفضلة والمشاركات.
- تمييز الـ48,772 مشاهدة الممولة من 48,861 مشاهدة لقصص الملف (89 غير إعلانية فقط)، وتوثيق اختلاف أوقات القياس مع Meta/TikTok.
- حفظ الملاحظات حول عدم اتساق إجمالي وقت مشاهدة قصص الملف (4.3 دقيقة مع متوسط 8 ثوانٍ ومشاهدات مرتفعة) حتى لا يستخدم في حسابات خاطئة.
- حماية مرجع v2 من التعديل والحذف بقواعد Firestore مقيدة بالمالك الوحيد، مع إتاحة قراءة v1 عند وجوده.

## تشغيل التحديث لمستخدم سبق أن رفع v1

1. **خذ نسخة احتياطية من السورس القديم**، ثم ارفع هذه النسخة الجديدة كاملة على مشروع الاستضافة المستقل (بدون خلط مجلدات من نسخ متفرقة). **لا تمسح أي بيانات من Firebase.**
2. في Firebase Console → Firestore Database → Rules، انسخ محتوى ملف **`firestore.rules`** الجديد واضغط **Publish**. هذه الخطوة أساسية: قواعد الإصدار القديم لا تتيح حفظ وثيقة v2.
3. تأكد أن `site/config.js` فيه Firebase UID الخاص بحسابك: `Wu4KHDIXQedFUMsSDt9yYLKSfhx1` (محدد مسبقًا هنا من UID الذي قدمته). إن تغيّر حساب المالك مستقبلًا، استخدم `node scripts/configure-owner.mjs NEW_UID` **ثم انشر القواعد الجديدة**.
4. افتح الموقع بعد النشر وسجّل الدخول بحسابك الحالي، ولا تنشئ مستخدمًا آخر. إذا كان مرجع v1 محفوظًا ستراه مع تنبيه **«المرجع القديم محفوظ — يلزم إضافة Snapchat»**.
5. ادخل **«المرجع الأساسي»**، وفي خانة **«استكمال Snapchat — المرجع v2»** اختر الملف `data/MZJ-baseline-2026-v2.json` من جهازك. هذا الملف موجود في **جذر السورس خارج site** لأسباب خصوصية.
6. راجع الأرقام المعروضة (4,878 متابعًا، 48,861 مشاهدة لقصص الملف منها 48,772 إعلانات، 725 للقصص العامة و747 لـSpotlight)، واضغط **«تثبيت المرجع في Firebase»** ثم **تأكيد**.
7. أعد تحميل الصفحة: سيعرض السيستم 4/4 منصات، ويقرأ من `baselines/baseline-2026-v2`. المرجع v1 القديم يبقى بلا تغيير.

**إذا كنت لم ترفع v1 أصلًا:** انشر القواعد الجديدة، سجل الدخول ثم اختر نفس ملف v2 في شاشة الاستيراد الأولى وثبته. لا حاجة إلى استيراد v1 أولًا.

**لو ظهرت رسالة صلاحيات:** تأكد أن القواعد المنشورة هي الخاصة بـv2، وأن حساب Firebase Authentication يملك UID أعلاه، وأن مشروع Firestore المختار هو `new-marketing-eaf85`. إذا كنت قد استوردت ملف v2 ولكن الحفظ رُفض، سيبقى الملف معروضًا في الجلسة لتعيد محاولة الحفظ بعد تحديث القواعد.

## هيكل المشروع

```text
README.md
firestore.rules                  # انسخ قواعد v2 الجديدة وانشرها
firebase.json
vercel.json
site/                            # الملفات التي تُنشر للزوار
  index.html
  app.js
  styles.css
  config.js                      # Firebase config + OWNER_UID
  firebase.js
  baseline.js                    # هيكل عام دون أرقام الحسابات
  favicon.svg
data/                            # لا تنشره علنًا
  MZJ-baseline-2026-v1.json      # نسخة تاريخية مرجعية للرجوع فقط
  MZJ-baseline-2026-v2.json      # المرجع المكتمل لاستيراده مرة واحدة
scripts/
  configure-owner.mjs            # اختياري إذا تغير UID المالك
  qa-render.mjs                  # اختبار عرض الواجهة دون Firebase
  qa-migration.mjs               # اختبار تحديث v1 إلى v2 دون حذف
MZJ-visual-preview.html          # معاينة محلية فقط — خارج site
MZJ-Snapchat-preview.html        # معاينة سناب محلية فقط — خارج site
```

## النشر

### Vercel

- اختر **Framework Preset = Other**، وجذر المشروع هو جذر السورس، و**Output Directory = site**.
- لا تحتاج Build Command أو npm.
- `vercel.json` في الجذر يحدد مجلد `site` مسبقًا.
- في Firebase Authentication > Settings > Authorized domains أضف نطاق المشروع المنشور إذا لم يكن موجودًا.

### Firebase Hosting

- الملف `firebase.json` يحدد `site` كمجلد `public`.
- ينشر ملف `firestore.rules` للقواعد عند استخدام أدوات Firebase CLI المناسبة للمشروع، أو انسخه يدويًا إلى Console.

### التشغيل محليًا

```bash
python -m http.server 8080 --directory site
```

ثم افتح `http://localhost:8080`. ملفا المعاينة `MZJ-visual-preview.html` و`MZJ-Snapchat-preview.html` للعرض الثابت ولا يتصلان بالقاعدة.

## الخصوصية والأمان

- المشروع يستخدم Firebase Web Config العام بطبيعته، **وليس** مفتاح Service Account؛ الحماية تعتمد على Authentication وFirestore Rules المرفقة.
- UID واحد فقط مسموح له بقراءة الوثيقتين v1/v2، وإنشاء v2 مرة واحدة. لا توجد عمليات تعديل أو حذف للمرجع التاريخي.
- أرقام المنصات **غير مضمّنة في ملفات `site/` المنشورة**. ملف v2 موجود خارج `site/`، ويُقرأ محليًا من اختيار المستخدم، ثم يُحفظ في Firestore بموافقة صريحة.
- لا تنشر ملفات `data/` أو المعاينات المحلية أو ملفات الحسابات الخاصة في موقع عام. إذا اخترت Output Directory `site` فلن تُنشر البيانات معها.
- لا توجد أي اتصالات أو عمليات كتابة إلى CRM أو نظام التسويق الحالي أو حسابات المنصات.

## الدقة المنهجية

- Facebook وInstagram: قرابة 26 سبتمبر إلى 25 أكتوبر 2026. بعض TikTok من نافذة 28 يومًا وبعضه 7 أيام؛ أرقام TikTok التقريبية مميزة بعلامة ≈.
- Snapchat: 10 أكتوبر إلى 6 نوفمبر 2026؛ ليس لها إجمالي مشاهدات موحّد قابل للجمع بين أنواع المحتوى. زيارات الملف الشخصي 1,929 منها 658 من إعلانات.
- 445 تفاعلًا في Facebook و108 في Instagram إجمالي **لا يُنسبان إلى العضوي**.
- Spotlight لديه 747 مشاهدة خلال آخر 28 يومًا، بينما مقاطع 1M/146K/37K المعروضة في الحساب تاريخية، وليست حصيلة نفس المدة.
- تقسيم الأعمار الوارد في Snapchat يخص الجمهور المتفاعل مع القصص، ولا يمكن تعميمه على المتابعين؛ فلتر الجنس غير مؤكد.
- جميع الأرقام **مرجع ما قبل الاستراتيجية** وليست تحديثًا لحظيًا أو ادعاءً بزيادة المبيعات.
